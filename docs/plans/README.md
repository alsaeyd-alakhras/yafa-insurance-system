# خطة تنفيذ نظام بطاقات التأمين — yafa-insurance-system

هذا المجلد يحتوي خطة التنفيذ الكاملة لبناء نظام بطاقات التأمين الطبي فوق مشروع Dashboard جاهز (Laravel + Fortify + Blade + Bootstrap admin template)، بالاستناد إلى وثيقة التحليل الكاملة بـ `docs/reference/`.

## المرجع الملزم

قبل أي تنفيذ، القواعد والكيانات محسومة نهائياً في:
- `docs/reference/00-overview.md` → `05-use-cases.md`
- `CLAUDE.md` (جذر المشروع) — القواعد الحرجة التي لا تُخالَف

هذه الخطة **لا تُعيد النقاش** بقواعد العمل (الرصيد الشهري، منع الازدواجية، الخصم بالـ snapshot...) — فقط تحدد **كيف** نبنيها فوق الكود الحالي.

## اكتشاف مهم أثناء الفحص

**لوحة التحكم الحالية بأكملها تفشل (500) على أي طلب.** السبب: `bootstrap/app.php` يسجّل alias باسم `ensure.phone` يشير لكلاس `App\Http\Middleware\EnsurePhoneIsSet` **غير موجود فعلياً بالكود**، وهذا الـ middleware مطبّق على كل route بـ `routes/dashboard.php`. هذا يُصلَح كأول خطوة بالمرحلة 1 — ما هو مرتبط بطلب المستخدم مباشرة، لكنه يمنع اختبار أي شي لاحقاً إذا ما تم إصلاحه أولاً.

## الأسئلة المفتوحة — محسومة بالكامل

كل الأسئلة الثمانية التي طُرحت أثناء التخطيط تمت الإجابة عليها من المستخدم — التوثيق الكامل لكل قرار بـ [`open-questions.md`](open-questions.md). **الخطة جاهزة للتنفيذ الفعلي، لا قرارات معلَّقة.**

## قرارات محسومة (من نقاش مع المستخدم)

1. **`activity_logs`**: نستخدم الجدول/الموديل/الـ Service الموجودين حالياً كما هم (`user_id, user_name, ip_request, ip_address, event_type, model_name, message, old_data, new_data`) بدل تعديلهم ليطابقوا `01-entities.md` حرفياً. أي كود جديد يستدعي `ActivityLogService::log(...)` الموجود.
2. **Currency + Report**: يُحذفوا بالكامل (Controller, Model, Migration, Policy, Observer, Views, Exports المرتبطة) — غير متعلقين بمجال التأمين إطلاقاً وغير مطلوبين بالوثيقة.
3. **نظام الصلاحيات**: الاعتماد الكامل على `RoleUser` الموجود (صلاحيات فردية جزئية لكل مستخدم) كآلية الفحص الفعلية، وليس فقط فحص `role`. `role` يبقى للتصنيف العام + الصلاحيات الافتراضية عند الإنشاء فقط. `super_admin` يبقى bypass عام وحيد. تفصيل كامل بـ `phase-2-auth-authorization.md`.
4. **حذف الزيارات**: مسموح فعلياً (hard delete) — الأدمن (أو أي صاحب صلاحية `visits.delete`) يحذف أي زيارة، الاستقبال (صلاحية `visits.delete-own`) يحذف فقط زياراته هو.
5. **حذف الموظفين/التابعين**: الأدمن بحرية كاملة (بالصلاحية المناسبة)، الاستقبال بدون صلاحية حذف/تعديل إطلاقاً (عرض فقط افتراضياً).
6. **حذف المستخدمين**: ممنوع حذف الذات دائماً؛ `super_admin` يحذف أي حساب؛ أدمن عادي لا يحذف أدمن آخر حتى لو يملك الصلاحية؛ استقبال بصلاحية ممنوحة صراحة يقدر يحذف (ضمن نفس قيد عدم حذف الأدمن).
7. **سبب رفض الاستبيان**: لا يوجد — رفض بسيط بدون حقل سبب.
