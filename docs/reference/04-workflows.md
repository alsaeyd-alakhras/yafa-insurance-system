# تدفقات العمل (Workflows)

## 1. تدفق الاستبيان العام (Survey Submission Flow)

```
[موظف يفتح الرابط العام]
        │
        ▼
[يعبّي بياناته: الاسم، الهوية، الجنس، الحالة الزوجية، التبعية التنظيمية]
        │
        ▼
[فحص فوري: هل رقم الهوية موجود مسبقاً في employees / dependents / survey_submissions؟]
        │
   ┌────┴────┐
  نعم        لا
   │          │
[منع الإكمال]  [يكمل: إضافة التابعين إن وُجدوا (زوج/ة، أبناء، والدين)]
   │              │
   │        [فحص هوية كل تابع بنفس الطريقة]
   │              │
   │              ▼
   │        [إرسال الطلب → survey_submissions (status = pending)]
   │              │
   │              ▼
   │        [إشعار/ظهور الطلب في لوحة الأدمن]
   │              │
   │              ▼
   │        [الأدمن يراجع الطلب: موافقة أو رفض]
   │              │
   │         ┌────┴────┐
   │       موافقة      رفض
   │         │           │
   │   [إنشاء employees  [status = rejected]
   │    + dependents      [يُسجَّل في activity_logs]
   │    من raw_data]
   │         │
   │   [ربط created_employee_id]
   │         │
   │   [status = approved]
   │         │
   │   [تسجيل في activity_logs]
   ▼         ▼
[نهاية]   [نهاية]
```

**قيد زمني:** هذا التدفق بالكامل متاح فقط خلال أسبوع واحد من تاريخ إطلاق الرابط. بعد انتهائه، أي رابط جديد يُفتح يُظهر رسالة "انتهت فترة استقبال البيانات".

## 2. تدفق تسجيل زيارة جديدة (New Visit Flow)

```
[موظف استقبال يبحث برقم هوية المريض (موظف أو تابع)]
        │
        ▼
[النظام يحدد: هل المريض موظف أم تابع؟ ومين الموظف صاحب الرصيد المرتبط به؟]
        │
        ▼
[فحص: هل يوجد سجل visit لنفس المريض (patient_employee_id أو patient_dependent_id) بتاريخ اليوم؟]
        │
   ┌────┴────┐
  نعم        لا
   │          │
[توجيه لتعديل  [حساب مباشر: COUNT(visits) لهذا الموظف وتابعيه بالشهر الحالي < 2 ؟]
 الزيارة          │
 الموجودة]   ┌────┴────┐
   │        نعم         لا
   │         │           │
   │   [إنشاء visit جديد] [رفض + رسالة:
   │    (patient_employee_id أو  "انتهت زيارات
   │     patient_dependent_id    هذا الشهر"]
   │     حسب نوع المريض)]
   │         │
   │   [اختيار قسم/أقسام طبية للزيارة]
   │         │
   │   [لكل قسم: نسخ discount_percentage الحالي
   │    → applied_discount_percentage]
   │         │
   │   [إدخال اختياري: amount_before_discount لكل قسم]
   │         │
   │   [حساب تلقائي: amount_after_discount]
   │         │
   │   [تحديث totals على مستوى الزيارة]
   │         │
   │   [تسجيل activity_log: visit_created]
   ▼         ▼
[إعادة التوجيه لصفحة الزيارة القائمة لإضافة/تعديل الأقسام]
```

## 3. تدفق تعديل زيارة قائمة (Update Existing Visit Flow)

```
[موظف استقبال (أي موظف استقبال، ليس بالضرورة من سجّلها) يفتح زيارة قائمة لنفس اليوم]
        │
        ▼
[إضافة قسم طبي جديد لم يكن موجوداً، أو تعديل مبلغ قسم موجود]
        │
        ▼
[فحص: هل القسم مُضاف مسبقاً بهذه الزيارة؟]
        │
   ┌────┴────┐
  نعم        لا
   │          │
[منع التكرار،  [إضافة سطر جديد في visit_departments
 يُسمح فقط     مع applied_discount_percentage الحالي]
 بتعديل
 المبلغ]       │
   │           ▼
   │     [إعادة حساب totals على مستوى الزيارة]
   │           │
   │           ▼
   │     [تحديث last_updated_by]
   │           │
   │           ▼
   │     [تسجيل activity_log: visit_updated]
   ▼           ▼
      [نهاية]
```

**ملاحظة:** التعديل على زيارة **لا يُنشئ استهلاكاً إضافياً** من الرصيد الشهري — الاستهلاك يُحتسب مرة واحدة فقط عند الإنشاء الأول للزيارة.

## 4. تدفق إضافة/تعديل موظف مباشرة من الأدمن

```
[الأدمن يفتح لوحة إدارة الموظفين]
        │
        ▼
[إضافة موظف جديد أو فتح موظف قائم للتعديل]
        │
   ┌────┴────┐
 إضافة      تعديل
   │          │
[فحص تكرار   [تعديل الحقول: الاسم، الحالة الزوجية،
 الهوية]      التبعية التنظيمية، إلخ]
   │          │
[حفظ + ربط   [حفظ]
 organization_unit_id]
   │          │
[تسجيل        [تسجيل activity_log: بحسب نوع التعديل]
 activity_log:
 employee_added_by_admin]
   ▼          ▼
      [نهاية]
```

**حالة خاصة:** إضافة تابع جديد لموظف قائم (مثال: مولود جديد) تتبع نفس منطق فحص تكرار الهوية، وتُسجَّل كحركة منفصلة في `activity_logs`.
