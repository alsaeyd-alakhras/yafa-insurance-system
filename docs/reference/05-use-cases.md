# حالات الاستخدام (Use Cases)

## Admin

### UC-A1: إدارة الهيكل التنظيمي
- **الفاعل:** Admin
- **الوصف:** إضافة/تعديل/حذف وحدات تنظيمية (مركز/دائرة/قسم) في الجدول الشجري `organization_units`.
- **المدخلات:** اسم الوحدة، الوحدة الأم (parent_id) إن وُجدت.
- **المخرجات:** وحدة تنظيمية جديدة أو معدَّلة، جاهزة للربط بالموظفين.
- **قاعدة مرتبطة:** الاستيراد الأولي من الجداول الثلاثة القديمة يُعاد ترتيبه هرمياً هنا (مرة واحدة عند الإطلاق).

### UC-A2: إضافة/تعديل موظف مباشرة
- **الفاعل:** Admin
- **الوصف:** إدخال بيانات موظف جديد أو تعديل بيانات موظف قائم دون المرور بالاستبيان.
- **المدخلات:** الاسم، رقم الهوية، الجنس، الحالة الزوجية، التبعية التنظيمية.
- **الفحوصات:** تفرّد رقم الهوية.
- **المخرجات:** سجل `employees` بحالة `active`، `source = admin`.

### UC-A3: إضافة/تعديل تابع لموظف
- **الفاعل:** Admin
- **الوصف:** إضافة زوج/ة، ابن، أو أحد الوالدين لموظف قائم (مثال: مولود جديد)، أو تعديل بيانات تابع موجود.
- **الفحوصات:** تفرّد رقم الهوية، قيود النوع (spouse حسب جنس الموظف، parent بحد أقصى أب وأم واحد).
- **المخرجات:** سجل `dependents` مرتبط بالموظف.

### UC-A4: مراجعة والموافقة على طلبات الاستبيان
- **الفاعل:** Admin
- **الوصف:** عرض قائمة `survey_submissions` بحالة `pending`، مراجعة البيانات الخام، والموافقة أو الرفض.
- **المخرجات عند الموافقة:** إنشاء `employees` + `dependents` رسمية، تحديث `status = approved`.
- **المخرجات عند الرفض:** `status = rejected` مع إمكانية إضافة سبب (اختياري).

### UC-A5: إدارة الأقسام الطبية ونسب الخصم
- **الفاعل:** Admin
- **الوصف:** تعديل `discount_percentage` أو `is_active` لأي من الأقسام الطبية الأربعة.
- **ملاحظة:** التعديل يؤثر فقط على الزيارات المستقبلية (بحكم آلية الـ snapshot في `visit_departments`).

### UC-A6: إنشاء مستخدمي نظام
- **الفاعل:** Admin
- **الوصف:** إنشاء حسابات دخول لموظفي الاستقبال أو لأدمن آخر، وتحديد الدور.

### UC-A7: عرض سجل الحركات
- **الفاعل:** Admin
- **الوصف:** استعراض `activity_logs` الكامل لأي نشاط بالنظام (تصفية حسب النوع/المستخدم/التاريخ لاحقاً عند الحاجة).

## Receptionist (موظف الاستقبال)

### UC-R1: البحث عن موظف/تابع برقم الهوية
- **الفاعل:** Receptionist
- **الوصف:** إدخال رقم هوية لعرض بيانات الشخص (موظف أو تابع) والموظف صاحب الرصيد المرتبط به، مع عرض الرصيد الشهري المتبقي.

### UC-R2: تسجيل زيارة جديدة
- **الفاعل:** Receptionist
- **الوصف:** بعد تحديد المريض، فحص عدم وجود زيارة بنفس اليوم لنفس المريض، ثم فحص الرصيد الشهري، ثم إنشاء الزيارة واختيار الأقسام الطبية المشمولة.
- **حالة استثنائية:** إن وُجدت زيارة بنفس اليوم لنفس المريض → توجيه تلقائي لـ UC-R3 بدلاً من الإنشاء.
- **حالة استثنائية:** إن انتهى الرصيد الشهري (2/2) → رفض مع رسالة واضحة.

### UC-R3: تعديل زيارة قائمة (إضافة قسم / تعديل مبلغ)
- **الفاعل:** Receptionist
- **الوصف:** فتح زيارة موجودة لنفس اليوم، إضافة قسم طبي جديد لم يكن مشمولاً، أو تعديل المبلغ المدخل لقسم موجود.
- **ملاحظة:** لا يُستهلك رصيد إضافي عند هذا التعديل.

### UC-R4: عرض تفاصيل زيارات موظف
- **الفاعل:** Receptionist
- **الوصف:** استعراض كل الزيارات المسجَّلة لموظف معيّن (وتابعيه) ضمن الشهر الحالي أو تاريخياً، لغرض المتابعة (وليس كتقرير رسمي).

## Employee (غير مستخدم نظام)

### UC-E1: تعبئة بيانات الاستبيان
- **الفاعل:** Employee (بدون حساب دخول)
- **الوصف:** فتح الرابط العام خلال فترة الأسبوع المتاحة، تعبئة بياناته الشخصية وبيانات تابعيه.
- **الفحوصات:** تفرّد رقم الهوية لكل شخص يُدخَل (الموظف ثم كل تابع).
- **المخرجات:** سجل `survey_submissions` بحالة `pending`، بانتظار مراجعة الأدمن.
- **قيد:** غير متاح خارج نافذة الأسبوع المحددة.
