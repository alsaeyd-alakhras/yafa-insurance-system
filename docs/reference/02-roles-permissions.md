# الأدوار والصلاحيات (Roles & Permissions)

## الأدوار

النظام يعتمد دورين فقط على مستوى `users.role`، تُطبَّق الصلاحيات عبر **Gates / Policies** في Laravel.

| الدور | القيمة (enum) | الوصف |
|---|---|---|
| المدير (Admin) | `admin` | صلاحية كاملة على النظام |
| موظف الاستقبال (Receptionist) | `receptionist` | صلاحية محدودة على تسجيل/تعديل الزيارات فقط |

---

## مصفوفة الصلاحيات (Permission Matrix)

| العملية | Admin | Receptionist |
|---|:---:|:---:|
| إدارة الهيكل التنظيمي (organization_units) | ✅ | ❌ |
| إضافة/تعديل موظف مباشرة | ✅ | ❌ |
| إضافة/تعديل تابع (dependent) مباشرة | ✅ | ❌ |
| مراجعة طلبات الاستبيان (Survey Submissions) | ✅ | ❌ |
| الموافقة / الرفض على طلب استبيان | ✅ | ❌ |
| إدارة الأقسام الطبية ونسب الخصم | ✅ | ❌ |
| إنشاء مستخدمي نظام (users) وتحديد أدوارهم | ✅ | ❌ |
| عرض سجل الحركات (Activity Log) بالكامل | ✅ | ❌ |
| تسجيل زيارة جديدة | ✅ | ✅ |
| تعديل زيارة (بنفس يوم الإنشاء، لنفس المريض) | ✅ | ✅ |
| عرض رصيد موظف (المتبقي من الزيارتين) | ✅ | ✅ |
| البحث عن موظف/تابع برقم الهوية | ✅ | ✅ |
| عرض تفاصيل زيارات موظف معيّن | ✅ | ✅ |
| تعديل بيانات موظف/تابع (اسم، حالة زوجية...) | ✅ | ❌ |

---

## ملاحظات تصميمية

- الصلاحيات تُبنى على أساس **الدور فقط** في هذه المرحلة (لا صلاحيات جزئية إضافية داخل نفس الدور). أي تفصيل إضافي (مثلاً "استقبال يشوف فقط تابعيه التنظيميين") **غير مطلوب حالياً** حسب توضيح صاحب المشروع.
- `Receptionist` لا يملك صلاحية حذف أي سجل نهائياً — فقط إنشاء/تعديل الزيارات.
- كل عملية إنشاء/تعديل من قبل `Receptionist` تُسجَّل في `activity_logs` مع `user_id` الخاص به لضمان تتبع كامل.
- عمليات الأدمن الحساسة (تعديل نسبة خصم قسم، اعتماد طلب استبيان) تُسجَّل أيضاً في `activity_logs`.
