# نظام بطاقات التأمين الطبي — مؤسسة يافا

## نظرة عامة

نظام إدارة داخلي (Laravel) لإدارة التغطية التأمينية الطبية التي توفرها المؤسسة لموظفيها وعائلاتهم (الزوجات، الأبناء، الوالدين). النظام يدير رصيد الزيارات الشهري، تسجيل الزيارات عبر موظفي الاستقبال، وتطبيق الخصومات على الأقسام الطبية المشمولة.

## الهدف من النظام

- توفير زيارتين طبيتين شهرياً لكل موظف (تشمل الموظف وكل تابعيه) بخصم أو مجاناً حسب القسم الطبي.
- تمكين موظف الاستقبال من تسجيل الزيارات بسرعة ودقة مع منع الازدواجية.
- تمكين الإدارة (Admin) من إدارة بيانات الموظفين، الأقسام، الخصومات، والموافقة على الطلبات الواردة من الاستبيان.
- توثيق كل حركة (تسجيل/تعديل) بشكل كامل لضمان الشفافية عند الرجوع للسجلات مستقبلاً.

## نطاق المشروع (Scope)

### ضمن النطاق
- إدارة بيانات الموظفين والتابعين (زوجات، أبناء، والدين).
- إدارة الهيكل التنظيمي (مركز ← دائرة ← قسم) كجدول شجري واحد.
- إدارة الأقسام الطبية الأربعة (عيادات، مختبر، صيدلية، أشعة) ونسب الخصم الخاصة بكل قسم.
- تسجيل وتعديل الزيارات، مع منطق منع الازدواجية لنفس المريض بنفس اليوم.
- إدارة رصيد الزيارتين الشهري لكل موظف (يشمل تابعيه)، بتصفير تلقائي أول كل شهر ميلادي بدون تدوير.
- استبيان عام مؤقت (أسبوع واحد فقط) لجمع بيانات الموظفين مع موافقة الأدمن قبل الاعتماد.
- سجل حركات (Audit Log) لكل العمليات الجوهرية: تسجيل/تعديل الزيارات، الموافقات، إضافة الموظفين.
- نظام صلاحيات بدورين: **Admin** و **Receptionist** (موظف استقبال/كاتب).

### خارج النطاق (المرحلة الحالية)
- التقارير (Reporting) — ستُضاف في مرحلة لاحقة بعد استقرار النظام الأساسي.
- أي تكامل مع أنظمة مالية أو محاسبية خارجية.
- تفاصيل الأدوية أو الفحوصات داخل كل قسم — يُكتفى بمبلغ إجمالي قبل/بعد الخصم لكل قسم.

## المستخدمون (Actors)

| الدور | الوصف |
|---|---|
| **Admin** | يدير بيانات الموظفين، الهيكل التنظيمي، الأقسام الطبية ونسب الخصم، يوافق على طلبات الاستبيان، صلاحية كاملة على النظام. |
| **Receptionist (كاتب/استقبال)** | يسجل الزيارات، يعدّل عليها في نفس اليوم، يشوف رصيد الموظف المتبقي. |
| **Employee (غير مستخدم نظام)** | يعبّي بياناته عبر رابط الاستبيان المؤقت فقط، لا يملك حساب دخول للنظام. |

## الافتراضات والقيود (Assumptions & Constraints)

1. رقم الهوية (9 أرقام) هو المعرّف الفريد لكل شخص (موظف أو تابع) في النظام.
2. الحصة الشهرية (زيارتان) على مستوى الموظف كوحدة كاملة — تشمل الموظف وكل تابعيه بلا استثناء وبلا تمييز.
3. الزيارة الواحدة = مريض واحد + يوم واحد. نفس المريض بنفس اليوم = تعديل على نفس الزيارة (لا تُنشأ زيارة جديدة).
4. الرصيد الشهري لا يتراكم (No rollover) — يُصفَّر تلقائياً أول كل شهر ميلادي.
5. الخصم ثابت على مستوى القسم الطبي (وليس لكل موظف على حدة)، يُحدَّد من الإدارة، ويُسجَّل كـ snapshot وقت الزيارة.
6. الهيكل التنظيمي (مركز/دائرة/قسم) بيانات موجودة مسبقاً بثلاث جداول، وستُعاد هيكلتها كجدول شجري واحد (self-referencing) داخل النظام الجديد.
7. رابط الاستبيان العام يعمل لمدة أسبوع واحد فقط من الإطلاق، ثم يُلغى نهائياً. أي إضافة لاحقة تتم من الإدارة مباشرة.
8. لا يوجد تقارير في هذه المرحلة — البيانات تُبنى بشكل يسمح بإضافتها لاحقاً بسهولة.
